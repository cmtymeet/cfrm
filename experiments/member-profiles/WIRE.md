# Member-client socket boundary

This experimental adapter wraps the existing signed, anonymous-eligibility profile protocol. It is client-owned: no operator listener, profile storage, reader lookup or report flow is introduced. Crow repository 9, pipeline 11 executed the fail-first source `a0a321a3efacc69aab450ee2b78436acca7df121`: the prior 23 protocol tests passed, 15 new socket tests failed against explicit stubs, and one negative configuration case passed the rejecting stub. That negative result alone establishes no implementation guarantee. The subsequent implementation and additional pending-work capacity regression await their hosted run.

Each frame is a four-byte unsigned big-endian byte length followed by exactly that many bytes of the existing UTF-8 JSON envelope. Length must be positive and at most the explicit `maxFrameBytes`, with a hard ceiling of 1 MiB. There is no delimiter, compression, URL, attachment or new cryptographic envelope. Native clients can implement the same framing around the established protocol bytes. A frame has one absolute deadline spanning its header and body; incoming bytes do not extend it. Write completion is also bounded. Malformed, truncated, timed-out or cancelled operations terminate the connection. No frame may be pipelined while another request is being handled.

`createFramedSocket(socket, { maxFrameBytes, frameTimeoutMs })` owns a connected Node socket and exposes `read()`, `write(bytes)` and `close()`. Only one operation may be outstanding. `frameTimeoutMs` is explicitly configured in 1..60000 milliseconds.

`startProfileWireService({ owner, endpoint, leaseExpiresAt, bindHost, clock, limits, onionServiceProvider, verifyPublication })` binds an ephemeral TCP port only on literal `127.0.0.1` or `::1`. `limits` explicitly contains `maxFrameBytes`, `frameTimeoutMs`, `sessionTimeoutMs` (1..300000) and `maxConnections`. The owner is disconnected before startup. The service asks `onionServiceProvider.publish({ endpoint, localAddress, signal })` to publish that exact forwarding target. The resulting publication must have a loss `signal` and `close()` operation. The mandatory trusted `verifyPublication({ publication, endpoint, localAddress, signal })` callback must establish that the app controls the advertised onion service and its exact forwarding mapping. Service startup has the same absolute bound as a session. Missing verification, failed verification or a mismatched route must leave the owner disconnected. The return value exposes only `localAddress`, `disconnect()` and a `closed` promise.

The provider/verifier is application-owned integration code, never peer input. A future Tor adapter can use an authenticated control connection and `ADD_ONION` with an explicit loopback target, control-connection lifetime, and no `Detach` or `NonAnonymous` flag. This experiment does not include that adapter and does not establish that a caller-supplied callback verifies Tor correctly. There is no default verifier. Our synthetic provider is explicitly a test double; its success establishes only socket integration.

Before successful publication verification, connections are rejected. Afterwards each connection permits exactly `hello`/`challenge`, then `read`/`profile`, with the existing anonymous proof and owner signatures verified by `protocol.js`. Each response is enqueued only while the publication and owner lease remain active. The connection cap bounds accepted sessions, including idle and pending-proof sessions. Disconnect, observed publication loss, lease expiry and session expiry destroy sockets; late asynchronous handler or provider results cannot reactivate service or enqueue profile bytes. Bytes already queued to the operating system or received by a peer cannot be retracted. A fresh service instance is needed after closure. No profile text or reader identity is logged or added to rendezvous records.

`createOnionProfileTransport({ dialOnion, limits })` implements the protocol reader's `open(endpoint)` capability. It independently validates the checksum-valid v3 onion endpoint, then calls only the required trusted `dialOnion(endpoint, { signal })`. That integration must return a Node socket acquired through the application's mandatory onion transport. The adapter never resolves or directly connects to an onion host, IP address, DNS name or URL. Dial, idle wallet work and both exchanges are bounded by the session deadline. Dial cancellation must be honored by the host adapter; any socket returned after cancellation is destroyed.

Example deployments may choose the current protocol's 100000-byte frame cap, 30000-ms frame deadline and 120000-ms session deadline; these are examples, not defaults. Proof/profile byte limits remain separately enforced inside the protocol. The wire cap must accommodate the configured protocol frame cap.

Real loopback socket tests are framing and lifecycle evidence. They are **not evidence of Tor service ownership, IP privacy, a functioning onion network or traffic-analysis resistance**. The current test worker has no Tor executable, and this task installs none. Source/API portability is distinct from an executed Android or iOS adapter.
