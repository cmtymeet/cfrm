# Anonymous first-contact permits

A test-driven experiment using RFC 9474 blind RSA signatures and a SQLite ledger. The issuer spends a trusted allocation while seeing only a blinded request. Redemption supplies a random permit and signature, without an account or recipient ID. Real cryptographic and concurrency tests come before implementation.

The initial nine tests pass at `312134e` ([run 34257993433](https://github.com/corbet-labs/cfrm/actions/runs/34257993433)). Three further regressions failed at `d5aa264` and pass at `5251e93` ([run 34258369141](https://github.com/corbet-labs/cfrm/actions/runs/34258369141)): spend validity is rechecked under the SQLite write lock after cryptographic verification, concurrent expiry/pruning cannot resurrect spends, and distinct trusted issuer keys have distinct ledger domains. Issuance cheaply rejects missing or exhausted allocations before private-key operations.

An additional recipient-retry experiment uses `prepareRedemption(permit)` to create a recipient-generated random claim and `redeemIntroduction(context, ledger, redemption, clock)` to return `{accepted: boolean}`. A valid permit can be accepted by only one claim; that same claim can retry after a lost response or server restart while the epoch remains valid. The server retains a hash of the claim beside the random permit nullifier, without member/group identifiers. The recipient must durably persist the exact pending claim before submitting it and must never accept a sender-chosen claim. These three tests failed in [run 34259032989](https://github.com/corbet-labs/cfrm/actions/runs/34259032989) and passed at `3c447fc` in [run 34259174624](https://github.com/corbet-labs/cfrm/actions/runs/34259174624).

All **16 permit tests passed** at `a10bd27d4fa1cd1a50035b4d136604652511ac20` in [manual CI run 4](https://crow.corbet.ch/repos/9/pipeline/4), using Node 24.19.0 and an exact Git archive verified before execution. This includes the post-prune clock rollback regression: a durable scalar retirement floor prevents an expired epoch from being registered or spent again after restart even if the wall clock moves backwards. That regression first failed in [run 34259504389](https://github.com/corbet-labs/cfrm/actions/runs/34259504389). The combined manual run is red because a separate enrollment experiment deliberately still contained its test-first stub; the permit step passed.

All **20 permit tests pass** at `67017122c8a7333f6797d07bf748cf6e874ecf8d` in [manual CI run 23](https://crow.corbet.ch/repos/9/pipeline/23), with zero failures. The four added cases cover allocation and issuance across SQLite write-lock acquisition. Their initial [run 22](https://crow.corbet.ch/repos/9/pipeline/22) at `ccc0e4285127b8f08eab687a605d740b861000f7` executed all 20: the prior 16 and both live-window controls passed, while two expiry regressions failed because expired issuance persisted `issued=1` instead of zero and expired allocation created a row instead of leaving none. The fix passes the trusted clock into both transactions and checks validity after acquiring the write lock, before new effects; retirement checks also execute inside that transaction. It changes no schema, cryptographic protocol or controller policy.

The synthetic lock worker holds a real SQLite write transaction, independently confirmed by a busy-lock probe. After the caller's last pre-check, it advances a shared trusted clock before releasing the lock. This establishes expiry before the target transaction can acquire its lock; it does not assert a fixed blocking duration. Both live controls issue and redeem real blind permits. The helper is released and reaped on every path, and the expiry cases inspect persisted rows independently of the returned error.

Issuance retry semantics remain unchanged: a fresh request that is already expired rejects at the public pre-check. An in-flight retry that reaches an already committed result retains its existing recovery path without another debit; the transaction's new validity guard applies before new issuance effects. This does not grant a general post-expiry retry window.

This is not a complete private reciprocity protocol. Network timing, anonymous redemption transport, malicious-recipient behavior, token transfer, allocation authentication and reward semantics remain separate. Cryptographic blindness does not imply traffic-analysis resistance. Each scope/epoch uses a fresh signing key shared across its members; never issue per-person identifying keys. The host must select a trusted immutable epoch catalog, provide trusted time, and restrict allocation/pruning methods to its own rules service. An expired pending attempt cannot be recovered after expiry merely by retrying its claim. Device snapshot freshness and crash-safe client commits are separate from server idempotency.

Run `npm ci --ignore-scripts` and `npm test` in this directory on a permitted test runner. Only synthetic data belongs in these tests.

Dependency: [Cloudflare blindrsa-ts](https://github.com/cloudflare/blindrsa-ts), Apache-2.0; protocol [RFC 9474](https://www.rfc-editor.org/rfc/rfc9474.html). Repository-authored experiment code uses the root license.
